\section{1. Contexto}

Esta guía describe el flujo técnico actualizado del proyecto Linker: instalación local, comandos de desarrollo y opciones de despliegue.

\textbf{Repositorio:} \url{https://3.n-la-c.app/gh-linker3} \\
\textbf{Producción:} \url{https://3.n-la-c.app}

\section{2. Requisitos}

\begin{itemize}
  \item Node.js 22 o superior
  \item npm
  \item (Opcional) Terraform y Docker para despliegue local de paridad
\end{itemize}

\section{3. Instalación y ejecución local}

Clonar e instalar:

\begin{lstlisting}
git clone https://github.com/co-eiv-devsecops/linker3.git
cd linker3
npm ci
cp .env.example .env
npm start
\end{lstlisting}

Abrir en el navegador: \texttt{http://localhost:3000}

\section{4. Comandos de desarrollo}

Todos los comandos se ejecutan desde la raíz del repositorio:

\begin{lstlisting}
npm start
npm test
npm run test:coverage
npm run test:coverage:check
npm run typecheck
npm run lint
npm run format
npm run check
\end{lstlisting}

\section{5. Arquitectura y estructura actual}

El proyecto implementa arquitectura por capas:

\begin{itemize}
  \item Domain: entidades y contratos de negocio.
  \item Application: casos de uso y validaciones.
  \item Infrastructure: adaptadores técnicos (SQLite, logger, generador).
  \item Presentation: endpoints HTTP y enrutamiento.
  \item Composition root: ensamblado en \texttt{src/container.ts}.
\end{itemize}

Estructura de referencia:

\begin{lstlisting}
linker3/
|-- src/
|   |-- domain/
|   |-- application/
|   |-- infrastructure/
|   |-- presentation/
|   |-- composition/
|   |-- config.ts
|   |-- container.ts
|   +-- main.ts
|-- test/
|-- public/
|-- scripts/
|-- docs/
|-- infra/
|-- cloud-init.yaml
|-- .env.example
+-- package.json
\end{lstlisting}

\section{6. Variables de entorno}

\begin{itemize}
  \item \texttt{PORT} (default: \texttt{3000})
  \item \texttt{BASE\_URL} (default: \texttt{http://localhost:\{PORT\}})
  \item \texttt{DB\_PATH} (default: \texttt{linker.db})
\end{itemize}

\section{7. Despliegue}

\subsection{7.1 Opción A: VM con cloud-init}

Usar \texttt{cloud-init.yaml} como script de inicialización de una VM Ubuntu 22.04+.
La provisión instala Node.js 22, clona el repositorio en \texttt{/opt/linker},
configura \texttt{systemd} y Nginx.

Verificar servicios:

\begin{lstlisting}
sudo systemctl status linker
sudo systemctl status nginx
\end{lstlisting}

TLS manual (una vez el dominio resuelva a la VM):

\begin{lstlisting}
sudo certbot --nginx -d <su-dominio>
\end{lstlisting}

\subsection{7.2 Opción B: Terraform en Oracle Cloud}

\begin{lstlisting}
cd infra/terraform-oracle
cp terraform.tfvars.example terraform.tfvars
terraform init
terraform apply
\end{lstlisting}

\subsection{7.3 Opción C: Paridad local con Terraform + Docker}

\begin{lstlisting}
cd infra/terraform
terraform init
terraform apply
\end{lstlisting}

\section{8. Actualización de despliegue en VM ya provisionada}

Para actualizar una instancia ya provisionada:

\begin{lstlisting}
bash infra/scripts/deploy.sh
\end{lstlisting}

El script ejecuta \texttt{git pull} en \texttt{/opt/linker}, reinicia \texttt{linker}
y muestra estado del servicio.

\section{9. CI/CD}

Workflows principales:

\begin{itemize}
  \item \texttt{.github/workflows/ci.yml}: validación general.
  \item \texttt{.github/workflows/ci-cd-dev.yml}: pipeline para rama \texttt{develop}.
  \item \texttt{.github/workflows/ci-cd-prod.yml}: pipeline para \texttt{main} y tags de release.
\end{itemize}

Los pull requests deben pasar CI antes de mergearse según branch protection del repositorio.
